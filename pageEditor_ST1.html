Home Page

Open Page Validation Evidence

Technical Description

The Home Page was built using a robust semantic HTML5 structure, strictly adhering to the shared template with <header>, <main>, and <footer> tags. Inside the <main> area, I used <section> containers to group distinct parts of the page.

  • Content Cards: I implemented the three mandatory action cards inside a .card-container. Each .card uses an intuitive structure combining an image, a heading, a descriptive paragraph, and an unordered list to highlight key actions.
  • Interactive Gallery: The "Main Topics" section serves as the interactive gallery. I use anchor tags wrapping images and text to create clickable cards that route users to the individual content pages.
  • Advanced Javascript Engines: Bubble Engine - I implemented a dynamic background using an HTML5 <canvas id="bubble-canvas">. The script utilizes the 2D context API to generate, animate, and recycle floating bubble objects, creating an immersive underwater effect.
    Scroll Reveal Engine - I used the modern IntersectionObserver API to monitor elements with the .reveal class. As the user scrolls and these elements enter the viewport, the script dynamically adds an .active class to trigger smooth CSS entrance animations.

Accessibility

I ensured the Home Page is accessible and inclusive by implementing the following practices:

  • Semantic Hierarchy: The page uses a logical heading structure starting with a single <h1> in the hero section, followed by <h2> for section titles, and <h3> for individual topic cards. This creates a clear document outline for screen reader users.
  • Descriptive Alt Text: Every image on the page includes a highly descriptive alt attribute that conveys context rather than just the file name (e.g., alt="Bleached coral reef affected by climate change" and alt="Ocean-cleaning robot in coastal waters").
  • Navigation Aids: I included a "↑ Top" anchor link at the bottom of the main content that links back to the #top ID, making it easier for keyboard-only users to jump back to the main navigation without excessive scrolling.

Gallery Page

Open Page Validation Evidence

Technical Description

The Gallery page was implemented as an interactive media hub using a combination of CSS Flexbox and custom JavaScript functions. The layout uses a <div class="gallery-grid"> container to organize image cards. Each card contains an image and a "View Details" button that triggers the JavaScript openExtended() function.
The core functionality of the page is the Extended View Modal. I wrote several JavaScript functions to handle the user interaction:

  • openExtended(title, imgSrc, desc): This function dynamically updates the modal's content using innerText and src properties before displaying the <div id="extendedView">.
  • Style Customization: I implemented changeStyle(theme) and changeSize(size) functions. These allow users to manipulate the DOM directly, changing the backgroundColor, color, and fontSize of the modal content in real-time.
  • Event Handling: A global window.onclick listener was added to ensure the modal closes if a user clicks outside the content box, improving the user flow.

Accessibility

Accessibility was integrated into the Gallery to ensure it is usable for all individuals:

  • Dynamic Accessibility Features: The inclusion of a "Change Style" and "Change Font Size" feature directly addresses accessibility by allowing users with visual impairments to switch to a high-contrast (Dark) mode or increase the text size for better readability.
  • Keyboard and Mouse Interaction: The modal is designed to be easily dismissed. I used a element with an onclick event, and the "click-outside-to-close" logic ensures users aren't "trapped" inside the modal view.
  • Alternative Text: Each image in the gallery includes descriptive alt attributes to provide context for users relying on screen readers.
  • Logical Structure: The page maintains the team's global

Content Page - Marine Pollution

Open Page Validation Evidence

Technical Description

The content page for "Marine Pollution" was developed using a clean, semantic HTML5 structure. The page is divided into logical segments using <section> tags, each identified with a unique id to enable Internal Linking.
Key technical implementations include:

  • Navigation & Anchor Tags: I implemented a local navigation menu using an unordered list (<ul>) where each <a> tag links to a specific section ID on the same page, allowing for seamless user movement.
  • Back to Top Feature: To improve the user experience on this long-form content page, I assigned id="top" to the <body> tag. I then placed a "Back to Top" link in the <footer> using an anchor tag (<a href="#top">), which provides a quick way for users to return to the header.
  • Structured Data: I utilized a combination of <h2> and <h3> tags to create a clear content hierarchy, and used <ul> and <li> tags to present the "Key Solutions" in an organized, readable list format.
  • Styling Consistency: The page links to both Global.css for shared team styles (like the header and footer) and a specific content_ST1.css to manage the unique layout and typography of this information-heavy page.

Accessibility

Accessibility was a core focus to ensure the environmental data is available to all users:

  • Skip-Link Behaviour: By utilizing internal section links, I provided a way for keyboard users and screen readers to skip directly to relevant information without having to tab through the entire header navigation every time.
  • Descriptive Alt Text: All informational images, such as the plastic bottle impact graphics, include descriptive alt attributes to ensure the message is conveyed to visually impaired users.
  • Logical Heading Levels: I strictly followed a descending heading order, ensuring that screen readers can generate an accurate document outline for the user.

Challenges & Lessons Learned

Managing Global Consistency

One of the primary challenges was developing the Global.css file to be used by all four team members. I had to ensure that the header, navigation, and footer styles were "bulletproof" so that when other students added their unique content, the layout wouldn't break. I learned the importance of using specific class naming conventions to avoid "CSS collisions," where a style meant for the Home page might accidentally change the appearance of the Feedback or Sitemap pages.

Optimizing the JavaScript Bubble Engine

Implementing the <canvas> bubble effect on the Home page presented a performance challenge. Initially, creating too many bubble objects caused the page to lag during scrolling. I learned how to optimize the animation loop using requestAnimationFrame() and how to "recycle" objects—resetting a bubble's position to the bottom of the screen once it floated off the top—rather than constantly creating and deleting new objects in memory.

Handling Asynchronous DOM Updates in the Gallery

In the Gallery, ensuring the openExtended() function correctly mapped the right image and description to the modal was difficult. I encountered a bug where the modal would occasionally show the previous image. This taught me a lot about how JavaScript interacts with the DOM and the importance of strictly passing parameters (title, src, desc) directly into the function to ensure the UI updates instantly and accurately.

Balancing Design and Accessibility

A significant lesson learned was that "cool" features can often create barriers for accessibility. I had to learn how to use CSS z-index properly to ensure the background canvas stayed behind the text so it didn't interfere with readability, and how to implement a "Close" function that works both with a button and a screen-wide click listener to help users navigate easily.

Team Integration and Version Control

As the person responsible for the main navigation, I had to constantly update the links as other students finished their pages. Coordinating these file names (e.g., ensuring everyone used content_ST2.html vs content-st2.html) taught me the necessity of clear team communication and creating a shared file-naming standard early in the project.

JANET Compliance

The development of the "Life Below Water" website was conducted in strict adherence to the JANET Acceptable Use Policy, which governs the use of the UK’s academic network. As Student 1, I ensured that the core infrastructure of the site—including the global styles and interactive elements—meets these professional and ethical standards.


First, I ensured that all content remains strictly educational and non-commercial. The Home page and the Plastic Pollution content page are designed solely to raise awareness about Marine Pollution. In compliance with JANET’s "Purpose of the Network" regulations, the site contains no advertisements, for-profit activities, or unauthorized commercial lobbying, ensuring the academic integrity of the project.


Second, I addressed the regulation regarding Network Disturbance. JANET prohibits any activity that causes an unreasonable load on the network or degrades performance for other users. To comply with this, I optimized the "Bubble Engine" on the Home page. By using requestAnimationFrame and recycling bubble objects within the <canvas> element instead of constantly creating new ones, I ensured the JavaScript is memory-efficient and does not slow down the user's browser or the hosting environment.


Furthermore, I have respected Intellectual Property Rights. Every image used in the Gallery and on my content page includes descriptive context. By providing a comprehensive References section and using royalty-free assets where possible, I have ensured that the project does not distribute materials that infringe on copyright, which is a core violation of JANET policy.


Finally, I applied the principle of Inclusivity and Accessibility. JANET encourages the creation of resources that are usable by the entire community. I demonstrated this by building high-contrast "Dark Mode" and "Large Text" functions into the Gallery using JavaScript DOM updates. This realistic application of accessibility standards ensures that the environmental data we are publishing is available to all users, regardless of their physical or visual requirements. By maintaining this level of technical and ethical discipline, the pages I created remain fully compliant with the regulations governing academic web publication.
